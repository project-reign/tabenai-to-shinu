# 食べないと死ぬ：50日目の晩餐

二つの選択肢だけで50日目を目指す、ブラウザ向け怪食サバイバル・ノベルです。v4.6.0「森が目を覚ます」は、v4.5.0のSTORY 50、HARD 50、SURVIVAL 50「怪食サバイバル」と永続実績・記録・設定を一切変えず、画像・音・触覚を安全に差し替える演出基盤を追加します。

## 遊ぶ

GitHub Pagesで公開する場合のURLは次の形式です。

```text
https://project-reign.github.io/tabenai-to-shinu/
```

初回だけオンラインで起動すると、ゲーム本体と必須アイコンを含むcore shellが端末へ保存されます。アセット台帳と軽量な演出素材はbest-effortで個別保存されるため、台帳の一時障害や一枚の404があってもcore shellの導入とオフライン再起動を妨げません。未取得素材、未知のアセットID、404、画像の読込失敗があっても、既存の絵文字・本文と二択へ自動的に戻ります。

起動時はタイトル画面を表示します。

- **つづきから**：保存中のランを再開
- **はじめから**：STORY 50、HARD 50、SURVIVAL 50から選択
- **記録**：実績、エンディング一覧、通算統計
- **設定**：文字サイズ、動きを減らす、選択確認、自動スクロール、BGM／効果音の個別音量とミュート、触覚、軽量画像表示

STORY 50はv4.3.0の50日間をそのまま維持します。HARD 50は同じシーンとルートを、低い初期体力、強い空腹・継続ダメージ、厳しい運命判定で遊びます。SURVIVAL 50は毎日のイベントデッキが変化する新モードです。100 DAYSとENDLESSは今後のロードマップとしてロック表示されます。

### SURVIVAL 50「怪食サバイバル」

保存されたシードから毎日のイベントデッキを組み、原則として1イベントの解決で1日進みます。イベントは `common`、`uncommon`、`rare`、`conditional`、`milestone`、`final` に分類され、通常イベント16件以上、条件付きイベント8件以上、レアイベント6件以上を収録します。

- レア基本率は3%。危険段階に応じて上昇し、最大7%
- 長期間レアに遭遇しない場合はpityで救済
- イベントごとにcooldown、oneShot、最大遭遇回数を設定可能
- 直近3件の通常イベントは原則として再抽選しない
- 選ばれたイベントIDを決定時点で保存し、再読込でも再抽選しない
- イベント列、判定、結末の乱数は保存済みPRNGだけを使い、同一シードと同一選択列で完全再現
- 1日の解決ごとにSURVIVAL専用の空腹消耗が2進み、摂取や行動で残った累積毒・疲労・負傷と終盤の消耗を同じ日次処理で反映
- 選択肢へ公開危険度と期待効果を表示し、HP・空腹・仲間・公開フラグによって安全な選択が反転
- HP 0以下または空腹100以上でその場でランを終了
- 10日目「最初の備蓄」、20日目「空腹の徴税人」、30日目「同行者の席」、40日目「最後の献立表」、50日目「生存者の配膳」は固定遭遇

50日目は「保存食の箱」「生きている箱」「空の箱」「帰還の箱」から、二段階の二択で一箱を選びます。最後も「開封する／拒否する」の二択です。節目成功、仲間、拒否回数、未来の計画や低確率遭遇の記録は、クリア可否を塞がず称号・持ち帰る物・追加評価へ反映されます。レアイベントだけを原因とする不可避の即死はありません。

SURVIVAL 50では「野生の50日」「稀少遭遇」「運も実力」「孤独な生還」「拒否の達人」「全ては予定通り」と、隠し実績「普通がいちばん」を永続記録へ追加します。

インストール・更新、共有、セーブ移行はタイトル画面の管理メニューにあります。ゲーム中の管理操作はヘッダー右端の `☰` にあります。

- インストール・更新
- 遊び方
- シードの確認
- 共有
- セーブ移行
- 手動保存
- 最初から
- タイトルへ戻る

新版が待機中になると画面下部へ通知が表示されます。「更新する」を選ぶまで現在の版を維持するため、プレイ中の不意な再読み込みはありません。進行は更新前に既存localStorageキーへ自動保存されます。

## v4.6.0 演出基盤「森が目を覚ます」

v4.6.0は演出の差し替え口を用意する基盤更新です。ゲームのイベント、数値、分岐、シード乱数、バランスには関与しません。正式なキャラクター絵、イベント絵、背景、BGMはv4.7で同じIDへ差し替える予定です。

`assets/manifest.json` が安定したアセットIDと画面・シーン・SURVIVALイベントへの割当を管理します。画面の演出領域は次の四層です。

1. 背景
2. キャラクター
3. 食べ物／イベントカード
4. 状態・雰囲気エフェクト

現行の同梱素材は、project-reignがこの更新用に作成した1600×900の抽象背景6点と800×800の簡易カード9点、合計30,069 bytesです。キャラクター6枠は絵文字フォールバックのみ、BGM 6枠は無音の差し替えスロットのみです。画像がなくてもゲームは完全に進行でき、本文・選択肢・結果の情報を画像、音、色、振動だけには依存させません。制作・配信規則は [`docs/ASSET_SPEC.md`](docs/ASSET_SPEC.md)、出典と利用条件は [`ASSET_LICENSES.md`](ASSET_LICENSES.md) に記録します。

演出フックはタイトル、通常、警告、レア、節目、最終局面、死亡、脱出、実績解除に分かれています。効果音は外部音源を使わず、10種類をWeb Audioで短く合成します。音声コンテキストは信頼された最初のポインター・タッチ・キー操作後にだけ開始し、画面が非表示になったときは停止します。対応端末では選択、警告、レア、死亡、脱出、実績解除などを短い触覚パターンでも通知します。

設定の「動きを減らす」とOS／ブラウザの `prefers-reduced-motion` のどちらかが有効なら、非本質的なアニメーションを抑制します。「画像演出を軽くする」は背景・キャラクター・カードを読み込まず、絵文字と本文を使用します。BGM／効果音それぞれの音量・ミュート、触覚、軽量画像表示は既存の `tabenai-to-shinu-meta-v1` とセーブ移行JSONへ保存されます。v4.6のBGM枠は無音で、設定画面にも正式BGMはv4.7で追加予定と表示します。

Service Workerはcore shell、presentation precache、lazy runtimeの三つの配信tierを区別します。物理cacheはcoreとpresentationの二つです。core shellだけを必須installとし、アセット台帳はbest-effortで取得します。台帳を取得できた場合も演出素材は一件ずつ取得し、HTTP 200だけをpresentation cacheへ保存するため、一枚の404でinstall全体を失敗させず、404 responseも保存しません。lazy素材はinstall時に除外し、初回の取得成功後にpresentation cacheへ保存します。現在の15点は小さなprecache素材で、将来追加するキャラクター画像やBGMは必要になった時点で遅延取得します。GitHub Pagesのサブパス相対URL、初回オンライン後のオフライン起動、プレイヤーが選ぶ明示更新は従来どおりです。

## ゲーム上の保証

- 各画面の選択肢は常に二つ
- 食べない、飲まない、何もしないという拒否を選択可能
- 白い土、赤い土、灰色の土、身体発芽の黒豆ルートを維持
- 最後の晩餐は四皿を二段階の二択で選択
- SURVIVAL 50の50日目は四箱を二段階の二択で選び、最後に開封／拒否を選択
- 同一シードと同一選択列で乱数結果を再現
- STORY 50でv4.3.0の全シーン・分岐・数値処理を維持
- HARD 50でも保存済みPRNGにより同一シード・同一選択を再現
- SURVIVAL 50でも全シーンを常時二択とし、食物・飲料・薬・待機イベントの拒否権を維持
- SURVIVAL 50のイベント決定と結果を保存済みPRNGで再現し、決定済みイベントは再読込で固定
- 選択肢の種別と本人の摂取判定を分離し、保護・持ち運び・譲渡では食べた回数や摂取実績を増やさない
- SURVIVALの判断用シミュレーションはゲーム保存PRNGと独立し、humanLikeは表示中の危険度・説明、HP、空腹、仲間、公開済みフラグだけを参照
- v2、v3、v4.2.1、v4.3.0のlocalStorageセーブをSTORY 50として正規化
- ランを消しても残る永続実績、エンディング記録、統計、設定
- 23件の既存実績と全記録を維持
- 演出素材の有無、読込順、音声・触覚設定によってゲーム結果や保存PRNGを変えない

ランの保存スキーマは v4.2.1 と同じ `version: 4`、保存キーは `tabenai-to-shinu-50days-v4` のままです。モードがない旧セーブには自動的に `mode: "story"` を追加します。実績・記録・設定は `tabenai-to-shinu-meta-v1` へ分離して保存します。アプリの表示バージョン `4.6.0` と保存スキーマを分離しているため、更新によって既存の進行を失いません。

セーブ移行JSONはSURVIVAL 50の決定済みイベントを含むランデータと、実績・記録・設定を含む永続メタデータの両方を保持します。旧meta、`formatVersion: 1`、`formatVersion: 2` も引き続き読み込めます。

## ローカル開発

Node.js 24 以上を使用します。

```bash
npm ci
npx playwright install chromium
npm run serve
```

テストサーバーはGitHub Pagesと同じサブパスを再現します。

```text
http://127.0.0.1:4173/tabenai-to-shinu/
```
