# 食べないと死ぬ：50日目の晩餐

二つの選択肢だけで50日目を目指す、ブラウザ向け怪食サバイバル・ノベルです。v4.8.0「食卓の記憶庫」は、STORY 50、HARD 50、SURVIVAL 50「怪食サバイバル」の結果と演出を変えず、3セーブスロット、永続図鑑、詳細リザルト、運命コード、JST日替わりの「今日の献立」を追加します。

## 遊ぶ

GitHub Pagesで公開する場合のURLは次の形式です。

```text
https://project-reign.github.io/tabenai-to-shinu/
```

初回だけオンラインで起動すると、ゲーム本体と必須アイコンを含むcore shellが端末へ保存されます。アセット台帳と軽量な演出素材はbest-effortで個別保存されるため、台帳の一時障害や一枚の404があってもcore shellの導入とオフライン再起動を妨げません。未取得素材、未知のアセットID、404、画像の読込失敗があっても、既存の絵文字・本文と二択へ自動的に戻ります。

起動時はタイトル画面を表示します。

- **つづきから**：3スロットの一覧から保存中のランを再開
- **はじめから**：STORY 50、HARD 50、SURVIVAL 50と保存先スロットを選択
- **記録**：実績、図鑑、エンディング、最大30件のラン履歴、通算統計
- **設定**：文字サイズ、動きを減らす、選択確認、自動スクロール、BGM／効果音の個別音量とミュート、触覚、軽量モード（画像とBGM編成）

タイトルには、その日のJST日付から決まるSURVIVAL 50「今日の献立」も表示します。通信やオンラインランキングは使わず、同じ日付なら全端末で同じseedになります。

STORY 50はv4.3.0の50日間をそのまま維持します。HARD 50は同じシーンとルートを、低い初期体力、強い空腹・継続ダメージ、厳しい運命判定で遊びます。SURVIVAL 50は毎日のイベントデッキが変化する新モードです。100 DAYSとENDLESSは今後のロードマップとしてロック表示されます。

### SURVIVAL 50「怪食サバイバル」

保存されたシードから毎日のイベントデッキを組み、原則として1イベントの解決で1日進みます。イベントは `common`、`uncommon`、`rare`、`conditional`、`milestone`、`final` に分類され、通常イベント16件以上、条件付きイベント8件以上、レアイベント6件以上を収録します。

- レア基本率は3%。危険段階に応じて上昇し、最大7%
- 長期間レアに遭遇しない場合はpityで救済
- イベントごとにcooldown、oneShot、最大遭遇回数を設定可能
- 直近3件の通常イベントは原則として再抽選しない
- 選ばれたイベントIDを決定時点で保存し、再読込でも再抽選しない
- イベント列、判定、結末の乱数は保存済みPRNGだけを使い、同一シードと同一選択列で完全再現
- 1日の解決ごとにSURVIVAL専用の空腹消耗が2進み、摂取や行動で残った累積毒・疲労・負傷と終盤の消耗を同じ日次処理で反映
- 選択肢へ公開危険度と期待効果を表示し、HP・空腹・仲間・公開フラグによって安全な選択が反転
- HP 0以下または空腹100以上でその場でランを終了
- 10日目「最初の備蓄」、20日目「空腹の徴税人」、30日目「同行者の席」、40日目「最後の献立表」、50日目「生存者の配膳」は固定遭遇

50日目は「保存食の箱」「生きている箱」「空の箱」「帰還の箱」から、二段階の二択で一箱を選びます。最後も「開封する／拒否する」の二択です。節目成功、仲間、拒否回数、未来の計画や低確率遭遇の記録は、クリア可否を塞がず称号・持ち帰る物・追加評価へ反映されます。レアイベントだけを原因とする不可避の即死はありません。

SURVIVAL 50では「野生の50日」「稀少遭遇」「運も実力」「孤独な生還」「拒否の達人」「全ては予定通り」と、隠し実績「普通がいちばん」を永続記録へ追加します。

アプリ情報・更新、共有、データ管理はタイトル画面の「メニュー」にあります。ゲーム中の操作もヘッダー右端の `☰` から「メニュー」を開きます。

- アプリ情報・更新
- 遊び方
- 判定情報（「詳細な判定情報」が有効な場合だけ）
- 共有
- データ管理
- 手動保存
- 最初から
- タイトルへ戻る

新版が待機中になると画面下部へ通知が表示されます。「更新する」を選ぶまで現在の版を維持するため、プレイ中の不意な再読み込みはありません。進行は更新前に既存localStorageキーへ自動保存されます。

## v4.8.0 周回・記録基盤「食卓の記憶庫」

STORY 50、HARD 50、SURVIVAL 50のランを任意の3スロットへ保存できます。一覧にはモード、日数、HP、空腹、場面、仲間、最終プレイ日時を表示し、名前変更、複製、削除、確認付き上書きに対応します。v4.7以前の単一ランは最初の起動時だけスロット1へ移し、移行済みマーカーで重複コピーを防ぎます。現在選択中のスロットは従来の `tabenai-to-shinu-50days-v4` にもラン本体のままmirrorするため、既存の再開経路と旧版互換を維持します。

記録画面は次のタブに整理します。

- **実績**：既存23件を維持し、図鑑、3スロット、運命コード、今日の献立、累計拒否、詳細リザルトに関する10件以上を追加
- **図鑑**：食べ物、イベント、仲間／登場存在、エンディング。初回／最終遭遇、遭遇回数、モード、A／B、摂取／拒否、到達結果と関連素材を記録
- **エンディング**：未到達項目と到達済みの結末を分離表示
- **ラン履歴**：完了ランを新しい順に最大30件保存し、結果カード、選択タイムライン、共有文、運命コードを表示
- **通算統計**：従来の集計に、図鑑、履歴、日替わり挑戦の進捗を追加

図鑑は実際のランで遭遇または選択した時だけ更新します。未発見項目は `???` またはシルエットとし、隠し項目は名前、条件、画像も伏せます。debug表示、プレビュー、再描画、リロードだけでは解除・重複加算しません。関連画像を取得できない場合も、絵文字と本文で情報と進行を維持します。

詳細リザルトにはモード、日数、エンディング、称号、HP、空腹、摂取／拒否、仲間、記憶、豆ルート、レア遭遇、節目、四皿／四箱、持ち帰った物、解除実績、選択タイムラインと運命コードを残します。レア遭遇は同じイベントが複数回起きても発生日ごとに記録します。同じランIDは一度だけ登録し、ID生成と記録処理はゲームの保存PRNGを消費しません。

通常表示はプレイヤー向けの日本語名と物語表現だけを使い、生のseed、判定ロール、正確な成功率、内部ID、通信中のONLINE表示、保存形式やcache revisionを出しません。必要な場合だけ、設定の既定OFF「詳細な判定情報」または `?debug=1` で再現・診断値を表示できます。OFFLINE、更新失敗、保存失敗は通常表示でも通知します。タイトルとゲーム中の操作入口は「メニュー」、保存の持ち出しは「データ管理」、PWA操作は「アプリ情報・更新」です。

運命コードはゲーム版、モード、seed、明示選択列を自己完結形式で保持します。内容をプレビューしてから新しいスロットへ開始でき、同じコードならイベント列、判定、結末を再現します。「今日の献立」は `fnv1a32-jst-v1` でJSTの `YYYY-MM-DD` をハッシュし、たとえば `2026-08-01` はseed `1264873921` です。初回挑戦、最高到達日、クリア、死亡理由、選択数を端末内へ保存し、初回オンライン起動後は日替わり開始も含め完全オフラインで動きます。

セーブ移行JSONの新規書き出しは `formatVersion: 3` です。3スロット、active slot、meta、エンディング、図鑑、最大30件のラン履歴、日替わり記録を含む全体バックアップと、単一スロット書き出しを選べます。読み込み前に内容と上書き先をプレビューし、旧 `formatVersion: 1`／`2` はスロット1へ移します。詳細なキー、移行表、容量不足時の縮退規則は [`docs/SAVE_SPEC.md`](docs/SAVE_SPEC.md) に記載します。

## v4.7.0 正式アート・音響「いただきますの森」

暗い食卓、琥珀色の光、異常だが美味しそうな料理、少し可愛い人外、静かな不気味さを、黒・焦茶・金・深紅を基調とした自己完結SVGで描きます。正式背景8点（1600×900）、正式キャラクター10点（800×1200）、食べ物／イベントカード23点（800×800）の合計41点、106,134 bytesを同梱します。各SVGは日本語の `<title>` と `<desc>` を持ち、本文と一致するalt／subjectを台帳で検証します。外部画像、外部フォント、外部スクリプト、第三者素材は使用していません。

BGMは外部楽曲や録音サンプルを使わず、`music-engine.js` が保存PRNGと独立した固定シーケンスをWeb Audioで合成します。

| 場面 | 曲名 | 長さ | 再生 |
| --- | --- | ---: | --- |
| タイトル | 空の皿 | 51.428571秒 | loop |
| 通常遭遇 | 腹の鳴る森 | 56.470588秒 | loop |
| レア遭遇 | あり得ない一皿 | 40秒 | loop |
| 最終局面 | 五十日目 | 73.846154秒 | loop |
| 死亡 | 残された器 | 16秒 | non-loop |
| 脱出 | 朝食のない朝 | 56.25秒 | loop |

選択、警告、レア、節目、摂取、拒否、実績解除、死亡、脱出、メニューに加え、毒、疲労、負傷を区別する全13種のSEも実行時合成です。音声は信頼された最初のユーザー操作後にだけ開始し、BGM／SEの音量・ミュート、非表示時の停止、復帰、失敗時の無音フォールバックに対応します。制作・権利情報は「設定 → このゲームについて」で確認できます。開発用アセットギャラリーは通常導線に表示せず、`?debug=1` の技術情報からだけ開けます。

41点の正式SVGはpresentation precacheへ個別に保存します。asset manifestの503、一枚の画像404、音声API／decode失敗があってもcore Service Worker installは成功し、本文、絵文字、状態表示、二択だけで完全オフライン再起動と完走が可能です。制作・配信・容量規則は [`docs/ASSET_SPEC.md`](docs/ASSET_SPEC.md)、個別ファイルの来歴と利用条件は [`ASSET_LICENSES.md`](ASSET_LICENSES.md) に記録します。

## v4.6.0 演出基盤「森が目を覚ます」（履歴）

v4.6.0は演出の差し替え口を用意した基盤更新です。ゲームのイベント、数値、分岐、シード乱数、バランスには関与しません。v4.7.0はこの安定IDとフォールバック契約を維持したまま正式素材を割り当てます。

`assets/manifest.json` が安定したアセットIDと画面・シーン・SURVIVALイベントへの割当を管理します。画面の演出領域は次の四層です。

1. 背景
2. キャラクター
3. 食べ物／イベントカード
4. 状態・雰囲気エフェクト

v4.6.0時点の同梱素材は1600×900の抽象背景6点と800×800の簡易カード9点、合計30,069 bytesで、キャラクター6枠とBGM 6枠は空の差し替えスロットでした。画像がなくてもゲームを完全に進行できる設計はv4.7.0でも維持します。

演出フックはタイトル、通常、警告、レア、節目、最終局面、死亡、脱出、実績解除に分かれています。音声コンテキストを信頼された最初のポインター・タッチ・キー操作後にだけ開始し、画面が非表示になったときは停止する契約もv4.7.0へ継承します。対応端末では選択、警告、レア、死亡、脱出、実績解除などを短い触覚パターンでも通知します。

設定の「動きを減らす」とOS／ブラウザの `prefers-reduced-motion` のどちらかが有効なら、非本質的なアニメーションを抑制します。「軽量モード（画像とBGM編成を簡略化）」は背景・キャラクター・カードを読み込まず絵文字と本文を使用し、曲・長さ・ループを維持したままBGMの音数と装飾音を減らします。BGM／効果音それぞれの音量・ミュート、触覚、軽量モードは既存の `lightVisuals` 設定として `tabenai-to-shinu-meta-v1` とセーブ移行JSONへ保存されます。

Service Workerはcore shell、presentation precache、lazy runtimeの三つの配信tierを区別します。物理cacheはcoreとpresentationの二つです。core shellだけを必須installとし、アセット台帳はbest-effortで取得します。台帳を取得できた場合も演出素材は一件ずつ取得し、HTTP 200だけをpresentation cacheへ保存するため、一枚の404でinstall全体を失敗させず、404 responseも保存しません。lazy素材はinstall時に除外し、初回の取得成功後にpresentation cacheへ保存します。GitHub Pagesのサブパス相対URL、初回オンライン後のオフライン起動、プレイヤーが選ぶ明示更新は従来どおりです。

## ゲーム上の保証

- 各画面の選択肢は常に二つ
- 食べない、飲まない、何もしないという拒否を選択可能
- 白い土、赤い土、灰色の土、身体発芽の黒豆ルートを維持
- 最後の晩餐は四皿を二段階の二択で選択
- SURVIVAL 50の50日目は四箱を二段階の二択で選び、最後に開封／拒否を選択
- 同一シードと同一選択列で乱数結果を再現
- STORY 50でv4.3.0の全シーン・分岐・数値処理を維持
- HARD 50でも保存済みPRNGにより同一シード・同一選択を再現
- SURVIVAL 50でも全シーンを常時二択とし、食物・飲料・薬・待機イベントの拒否権を維持
- SURVIVAL 50のイベント決定と結果を保存済みPRNGで再現し、決定済みイベントは再読込で固定
- 選択肢の種別と本人の摂取判定を分離し、保護・持ち運び・譲渡では食べた回数や摂取実績を増やさない
- SURVIVALの判断用シミュレーションはゲーム保存PRNGと独立し、humanLikeは表示中の危険度・説明、HP、空腹、仲間、公開済みフラグだけを参照
- v2、v3、v4.2.1、v4.3.0のlocalStorageセーブをSTORY 50として正規化
- ランを消しても残る永続実績、エンディング記録、統計、設定
- 23件の既存実績とv4.8.0の追加実績、図鑑、履歴、日替わり記録を維持
- 演出素材の有無、読込順、音声・触覚設定によってゲーム結果や保存PRNGを変えない
- 3スロット、図鑑、ランID、運命コード、日替わりseedの生成でもゲーム保存PRNGを消費しない

ランの保存スキーマは v4.2.1 と同じ `version: 4` のままです。3スロットは `tabenai-to-shinu-run-slots-v1` へ保存し、active slotだけを従来キー `tabenai-to-shinu-50days-v4` へ互換mirrorします。モードがない旧セーブには自動的に `mode: "story"` を追加します。実績・設定は `tabenai-to-shinu-meta-v1`、図鑑、履歴、日替わり記録は各専用キーへ分離します。アプリの表示バージョン `4.8.0`、workspace `version: 1`、ラン `version: 4`、移行JSON `formatVersion: 3` は別の概念です。

セーブ移行JSONはSURVIVAL 50の決定済みイベントを含むランデータと、実績・記録・設定、図鑑、ラン履歴、日替わり記録を保持します。旧run、旧meta、`formatVersion: 1`、`formatVersion: 2`、`formatVersion: 3` を読み込めます。
