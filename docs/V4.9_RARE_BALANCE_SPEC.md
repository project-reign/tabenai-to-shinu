# v4.9.0 レアイベント頻度・テンポ調整仕様

## 目的

SURVIVAL 50のtrue rareを「一周で一回起こるか、起こらないか」へ調整する。条件付き・仲間・節目・最終イベントはtrue rareへ含めない。

## v4.8.0基準値

人間らしい判断方針では、10,001ラン中:

- 0回: 20
- 1回: 275
- 2回: 658
- 3回以上: 9,048
- 平均: 3.6587回
- pity発生ラン: 92.89%

現状は目標より明確に多い。

## 目標分布

50日完走ランを主評価とし、各方針100,000 seed以上で確認する。

- 0回: 45〜55%
- 1回: 35〜45%
- 2回: 5〜10%
- 3回以上: 0〜1%
- 平均: 0.55〜0.75回
- true rareは原則2回まで

死亡・餓死ランを含む全ラン分布も併記する。

## 調整方針

### 1. rare回数上限

- `rareSeen >= 2` ではtrue rare抽選を停止する
- ただしconditional／milestone／finalは通常どおり発生する
- 同一rareのoneShot、cooldown、maxEncountersは維持する

### 2. 基礎率

初期候補:

- 1〜19日: 0.8%
- 20〜34日: 1.0%
- 35〜44日: 1.2%
- 45〜49日: 1.5%

固定値ではなく、目標分布へ収まるよう校正する。

### 3. soft pity

現在の「14回未遭遇で強制」に近い挙動を廃止する。

- `rareSeen === 0` のランだけ対象
- 35〜40日目以降に開始
- 基礎率へ段階的な加算を行う
- 実効率上限は4%程度
- 発生保証はしない
- 一度true rareが出たらpityを解除
- pity hitは「基礎率では外れ、加算分で当たった場合」と定義する

これにより、レア未発生ランを残しながら極端な未遭遇だけを少し救済する。

### 4. ゲーム結果への影響

- rareが出ないことだけでクリア不能にしない
- rareイベントを生還の必須回復源にしない
- rare頻度低下で生還率が大きく変わる場合は、rare以外の通常回復・被害を最小限だけ再調整する
- STORY／HARDは一切変更しない

## シミュレーション

### 方針

- random
- allRefuse
- allConsume
- omniscientConservative
- humanLike

### 最低件数

- 校正時: 各10,001 seed
- 最終確認: 各100,000 seed

### 必須報告

方針別に:

- clear / death / starve / other
- 50日到達率
- 平均生存日数
- rare 0 / 1 / 2 / 3+回
- 平均rare回数
- natural hitラン率
- pity hitラン率
- 2回上限到達率
- longest drought分布
- 各rare eventの遭遇数
- 例外、無限ループ、不正値、cooldown／oneShot／recent違反

完走ランだけのrare分布と、全ランのrare分布を分けて出す。

## 演出・表示

- true rareだけに「稀少な遭遇」専用演出を使う
- conditionalは「因縁／仲間」
- milestoneは「節目」
- finalは「最終局面」
- 通常プレイヤーUIに確率、pity、event IDを表示しない
- 詳細な判定情報または`?debug=1`だけで確認可能

## 実機テスト

固定seedで最低10ランの手動プレイログを作る。

- 0 rareランを3本以上
